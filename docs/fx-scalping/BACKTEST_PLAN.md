# FX 5分足スキャルピングEA - バックテスト計画書

## 1. バックテスト概要

### 1.1 目的
- 各セットアップの有効性を定量的に検証
- 最適なパラメータ組み合わせを発見
- リスク調整後リターンの最大化
- 市場環境別パフォーマンスの把握
- ドローダウンと回復期間の分析

### 1.2 成功基準
```
必須達成項目:
- 勝率: 45%以上
- プロフィットファクター: 1.5以上
- 最大ドローダウン: 20%以下
- 月間平均収益: +5%以上
- リスクリワード比: 1:1.5以上

理想目標:
- 勝率: 55%以上
- プロフィットファクター: 2.0以上
- 最大ドローダウン: 10%以下
- 月間平均収益: +10%以上
- シャープレシオ: 1.5以上
```

## 2. テストデータ仕様

### 2.1 データ期間
```
Phase 1: 初期検証（最優先）
- 期間: 2024年1月〜2024年12月（1年間）
- 目的: 直近の市場環境での有効性確認

Phase 2: 中期検証
- 期間: 2022年1月〜2024年12月（3年間）
- 目的: 異なる市場環境での安定性確認

Phase 3: 長期検証
- 期間: 2020年1月〜2024年12月（5年間）
- 目的: コロナショック等の異常相場での耐性確認
```

```
主要通貨ペア（優先順位順）:

   - スプレッドが狭い

   - アジア時間に活発

5. EUR/JPY（オプション）
   - クロス円の代表
```

## 3. テストシナリオ

### 3.1 基本テスト

#### Test Case 1: デフォルトパラメータ
```
目的: ベースライン性能の確認
設定:
- 全パラメータをデフォルト値
- EUR/USD、2024年データ
- 固定ロット0.01
- スプレッド2pips固定

期待結果:
- 月間20-40トレード
- 勝率40%以上
- プロフィットファクター1.0以上
```

#### Test Case 2: 各セットアップ個別テスト
```
目的: 各セットアップの独立性能評価

2-1: パターンブレイクのみ
- パターンブレイクプラグインのみ有効
- ビルドアップ3-10本
- ブレイク確認2本

2-2: プルバックのみ
- プルバックプラグインのみ有効
- プルバック深さ30-70%
- EMAタッチ必須

2-3: コンビのみ
- コンビプラグインのみ有効
- 最小要因数2
- スコア閾値70

期待結果:
- 各セットアップの特性把握
- 最も有効なセットアップの特定
```

### 3.2 パラメータ最適化

#### 最適化対象パラメータ
```
優先度1（最重要）:
- ビルドアップバー数: 3-10 (step 1)
- ブレイク確認バー数: 1-3 (step 1)
- 損切り幅: 8-15 pips (step 1)
- 利確幅: 15-30 pips (step 1)

優先度2（重要）:
- EMA距離フィルター: 10-20 pips (step 2)
- プルバック深さ: 20-80% (step 10)
- ビルドアップ最大幅: 5-15 pips (step 2)

優先度3（調整）:
- 時間帯フィルター: ON/OFF
- スプレッドフィルター: 1-3 pips (step 0.5)
- ATRフィルター: 3-10 pips (step 1)
```

#### 最適化手法
```
Step 1: 遺伝的アルゴリズム
- 初期個体数: 100
- 世代数: 50
- 交叉率: 0.8
- 突然変異率: 0.1
- 評価関数: シャープレシオ

Step 2: グリッドサーチ（詳細調整）
- 上位5パラメータセットを選択
- 各パラメータ±20%の範囲で微調整
- ステップ: 5%

Step 3: ウォークフォワード分析
- IS期間: 6ヶ月
- OOS期間: 2ヶ月
- ローリング: 1ヶ月
```

## 4. パフォーマンス評価

### 4.1 評価指標

#### 収益性指標
```
基本指標:
- 総利益/総損失
- 純利益
- プロフィットファクター
- 期待値（1トレードあたり）
- 月間/年間収益率

詳細指標:
- 勝率
- 平均勝ち/平均負け
- 最大連勝/最大連敗
- ペイオフレシオ
- 月別収益の標準偏差
```

#### リスク指標
```
ドローダウン分析:
- 最大ドローダウン（金額）
- 最大ドローダウン（％）
- 平均ドローダウン
- ドローダウン期間
- リカバリー期間

リスク調整指標:
- シャープレシオ
- ソルティノレシオ
- カルマーレシオ
- オメガレシオ
- リカバリーファクター
```

#### 安定性指標
```
- 月間収益の一貫性
- 収益の正規分布性
- スキュー（歪度）
- カートシス（尖度）
- VaR（Value at Risk）
- CVaR（Conditional VaR）
```

### 5.3 リスクと対策

#### 技術的リスク
```
リスク: データ品質が低い
対策: 複数ソースからデータ取得、クロスバリデーション

リスク: 過学習（カーブフィッティング）
対策: ウォークフォワード分析、OOS検証

リスク: 実行環境の差異
対策: スリッページ/スプレッドの保守的設定
```

#### プロジェクトリスク
```
リスク: スケジュール遅延
対策: 優先順位付け、段階的実施

リスク: パフォーマンス未達
対策: 代替手法の準備、パラメータ範囲拡大

リスク: バグによる誤った結果
対策: 単体テスト強化、結果の妥当性確認
```
